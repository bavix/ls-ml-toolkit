# Инфраструктура: воркер обучения на своей машине (Nomad)

Как поднять машину с AMD 5600G (32 ГБ, без дискретной видеокарты) как воркер обучения YOLO,
которому можно слать задачи из этого репозитория, и что для этого нужно вернуть мне.

## Что это такое

Не сервис с открытым портом. Воркер сам ходит в S3 и опрашивает три префикса в одном бакете:

```
jobs/pending/<id>.json   — сюда кладётся задача при отправке
jobs/running/<id>.json   — воркер сам переносит сюда, пока считает
jobs/done/<id>.json      — результат (успех/ошибка), рядом jobs/done/<id>/weights/ — веса
```

Ничего слушать наружу не нужно — только исходящие запросы к S3. Одна задача единовременно:
машина выделяется не под постоянную нагрузку, а под редкие прогоны.

Обучение — на CPU. У Vega (встроенная графика 5600G) нет рабочего пути ROCm для обучения,
поэтому образ ставит CPU-сборку PyTorch, а не тянет бесполезный CUDA/ROCm-рантайм на несколько
гигабайт.

## Что нужно поднять

1. **S3-бакет** (или S3-совместимое хранилище) — куда я буду заливать датасет и откуда воркер
   будет забирать задачи и класть результат. Годится обычный AWS S3 или любой S3-совместимый
   (MinIO и т.п.) — воркер сам подставляет `endpoint`, если он не пуст.
2. **Docker-образ**, собранный из `Dockerfile.worker` в этом репозитории:
   ```bash
   docker build -f Dockerfile.worker -t <ваш-registry>/ihowmuch-tag-worker:latest .
   docker push <ваш-registry>/ihowmuch-tag-worker:latest
   ```
3. **Nomad job** — шаблон в `nomad/tag-worker.nomad.hcl`. Там помечено `# FILL` всё, что
   специфично для вашего кластера: датацентр, адрес образа, бакет, S3-креды, эндпоинт. Я не
   знаю топологию вашего Nomad, поэтому заполнить эти поля — на вашей стороне.
4. Запуск:
   ```bash
   nomad job run nomad/tag-worker.nomad.hcl
   ```

Ресурсы в шаблоне посчитаны под 5600G: 5 из 6 ядер, 24 из 32 ГБ — с запасом на систему.
Поправьте под фактическую нагрузку машины, если на ней крутится что-то ещё.

## Что вернуть мне после запуска

1. **Имя S3-бакета** и, если это не обычный AWS S3, **endpoint** хранилища.
2. **Регион**, если не `us-east-1`.
3. Подтверждение, что воркер запущен и опрашивает бакет — проще всего командой:
   ```bash
   lsml-worker status --bucket <бакет>
   ```
   (запустить локально с теми же S3-кредами; должно напечатать три пустых списка
   `pending`/`running`/`done` без ошибок — значит воркер и бакет видны друг другу).

С этими тремя вещами я смогу класть задачи через `lsml-worker submit` и они начнут забираться
воркером сами — без дальнейшей ручной настройки с моей стороны.

## Как я буду ставить задачи (для справки, ничего делать не нужно)

```bash
lsml-worker submit dataset/tag \
  --bucket <бакет> --base-model yolov8n.pt \
  --epochs 30 --patience 10 --freeze 10 --device cpu
```

Датасет (`dataset/tag/`) заливается вместе с задачей — воркеру не нужен доступ к вашей локальной
файловой системе или к моей.

## Честно про скорость

CPU-обучение на 6 ядрах — не гарантированно быстрее того, что уже идёт локально на Apple
Silicon (MPS). Смысл не в скорости одного прогона, а в том, что можно параллелить: пока один
рецепт считается здесь, другой — там, без взаимной конкуренции за одну машину.
